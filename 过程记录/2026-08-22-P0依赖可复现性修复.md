# 2026-08-22 P0 依赖可复现性修复

## 背景

桌面版（win-unpacked）启动即闪退：dsh 子进程 exit code 1，报错
`session artifact "...session.jsonl.zstd" uses .jsonl.zstd, but this backend is
configured for compression "none"`。

根因：打包进应用的 `@deepseek-ai/dsh-base/cordis.patch.yml` 把会话持久化
写死为 `compression: none`，而既有会话（CLI 产生）是 `.jsonl.zstd`，编码不匹配。
同一版本号 `0.1.1-rc.2` 在 npmmirror 与另一来源（官方源/旧快照）内容不同：
npmmirror 当前 tarball 无 `compression: none`（已验证 integrity
`sha512-DT1kSa...`），而应用内安装的那份带 `compression: none`。

## 修复内容（本次提交的源码改动）

1. `app/package.json`：`@deepseek-ai/dsh` 依赖去掉 `^`，改精确版本 `0.1.1-rc.2`。
2. `app/package-lock.json`：重新生成，与 `package.json` 一致（此前记录
   dsh-base 0.1.0-rc.6，与实际安装的 0.1.1-rc.2 失配，`npm ci` 不可用）。
3. `app/build/afterPack.js`：新增依赖守卫——打包后若
   `dsh-base/cordis.patch.yml` 含 `compression: none` 直接抛错终止构建；
   并打印打包的 dsh 版本与声明版本，便于追溯。
4. 安装依赖流程改为 `npm ci`（`app/README.md`、根 `README.md`）。
5. 运行期兜底：`~/.dsh/profiles/web/cordis.patch.yml` 显式
   `session-persistence-jsonl.compression: zstd`（本次会话已加，重新打包后
   仍可保留，双保险）。

## 验证

- 重新生成 lockfile 后 dsh-base 记录为 0.1.1-rc.2，integrity 与 npmmirror
  当前 tarball 一致。
- `npm ci` 后 `app/node_modules/@deepseek-ai/dsh-base/cordis.patch.yml` 不再含
  `compression: none`。
- 依赖守卫对旧的（含 compression:none）打包资源运行会抛错（预期行为），
  对新的依赖树通过。
