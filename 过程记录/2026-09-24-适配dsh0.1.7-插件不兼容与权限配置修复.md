# 2026-09-24 适配 dsh 0.1.7：插件不兼容、权限配置报错、壳守卫修复

> 环境：B机（全机安装，程序在 `D:\AI(CODEX)\dsh desktop\DS Harness Desktop`）
> 前置：本日已手工激活 `0.1.7-rc.2`（见 `2026-09-24-应用内更新自动回退bug与手工激活0.1.7.md`）

## 1. 现象：激活 0.1.7 后打不开

```
web boot: 1 entry did not activate
@mars-sea/dsh-commandcode-provider: pending (waiting for service: settingsScope)
```

### 根因：0.1.7 移除了 `settingsScope` 服务

从两侧独立验证：

| 引擎版本 | `@deepseek-ai/dsh-settings` 导出 |
|---|---|
| 0.1.5-rc.2 | `SettingsProvider` |
| 0.1.7-rc.2 | `SettingsForms`（`settingsScope` 在整棵树里零命中） |

旧版 provider（早于 `0.11.9`）`inject` 了 `settingsScope` → Cordis 永远等服务 → **条目永久 pending**
（不失败、不超时），插件树加载不完整。插件作者 CHANGELOG 0.11.9 原文即为此事：

> The engine replaced its settings.yaml document with schema-derived Config forms
> (`SettingsProvider` → `SettingsForms`, and `installSection` plus the browser's `settingsScope`
> service are both gone), so this release carries the two-generation adaptation…

### 修复：更新插件

`dsh plugin --profile web update @mars-sea/dsh-commandcode-provider@latest` → 装到 `0.11.11`（含双代适配）。

**注意：拿不到 0.11.14**，因为 pnpm 11 的供应链冷却期（见第 3 节）。

## 2. 附带发现并修掉：`defaultPreset: auto` 在 0.1.7 必定失败

修好插件后，日志最后一条是**另一个**失败（与插件无关）：

```
dsh: warning: 1 entry did not activate
permission (@deepseek-ai/dsh-permission-presets): Error: permission: unknown preset "auto"
    at PermissionPresetService.resolve (...0.1.7-rc.2...)
    at new PermissionPresetService (...0.1.7-rc.2...)
```

读 0.1.7-rc.2 源码，`app/profiles/web/cordis.patch.yml` 里的 `defaultPreset: auto` 必然抛错：

```js
L174:  this.presets = config.presets;   // 写了 presets: → 整体替换内置默认表
L176:  if ("auto" in this.presets) throw …            // auto 是保留字，不能出现在用户表里
L239:  get names() { return [...Object.keys(this.presets),
                         ...this.autoAdmit === void 0 ? [] : [AUTO_PRESET]] }  // auto 仅在 Auto 集成 live 时可选
L179-181: const defaultPreset = config.defaultPreset.get() ?? inferredDefault;
          this.resolve(defaultPreset);   // 构造函数里就解析 → autoAdmit 必然还不存在 → 抛错
```

**已修**：`defaultPreset: auto` → `defaultPreset: workspace-write`（保守值，等于本会话初始态；
想用 Auto 得去「插件管理 → 自动审阅」启用集成，不能写进 `defaultPreset`）。
改后用引擎自带 `js-yaml` 校验通过（5 个条目，permission 段解析正确）。

## 3. 关键知识：pnpm 11 默认有 1 天冷却期

`profiles/web/pnpm-workspace.yaml` 里的 `minimumReleaseAgeExclude` 暴露了机制：
**pnpm 11 起 `minimumReleaseAge` 默认 1440 分钟（1 天）**，供应链保护默认开启，
**刚发布的版本解析不出来**。实证：

| 包 | 最新发布 | 实际能装到 |
|---|---|---|
| `@mars-sea/dsh-commandcode-provider` | 0.11.14（09-24 12:46） | **0.11.11**（09-23 08:32） |
| `dshmarket` | 1.65.1（09-24 14:30） | **1.58.0**（`pnpm outdated` 的结论） |

要立刻装某版本须写进 `minimumReleaseAgeExclude`（该文件已有 3 条此类豁免）。
**排查"版本没升上去"先看这条，别怀疑镜像没同步**（两个源我都查了，dist-tags 一致）。
