# 2026-08-23 升级 dsh 到 0.1.1-rc.2（插件不变）

## 背景与目标

- 用户请求：升级 dsh 到最新版，**已安装的插件保持不变**。
- 升级前 dsh 版本：`0.1.0-rc.6`；npm dist-tag `latest` 最新版本：`0.1.1-rc.2`。

## 运行架构梳理（升级前调研）

- 桌面版（Electron 壳）打包产物在 `产出\win-unpacked\resources\app`，其
  `node_modules\@deepseek-ai\dsh`（0.1.0-rc.6）是**真正的运行态实现**。
- 用户日常启动：桌面 `启动-DeepSeek-Harness.bat` → `dsh web` →
  `C:\Users\Administrator\AppData\Roaming\npm\dsh.cmd` 硬编码 shim →
  `C:\Users\Administrator\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js`。
- `.dsh\profiles\node_modules` 是一个 **junction 农场**：`@deepseek-ai\*` 下 197 个包
  全部是 junction，指向 `产出\win-unpacked\resources\app\node_modules\@deepseek-ai\*`。
  即：升级 win-unpacked 里的真实目录，junction 农场与 shim 自动跟随。
- 用户插件（保持不变）：`C:\Users\Administrator\.dsh\profiles\web\` 下的
  `@liustack/modlens@3.16.7`、`@nanmicoder/dsh-auto-mode@^0.1.4`、
  `dsh-convo-cost@^1.0.0`、`dshmarket@1.5.0`，由 `web` profile 的 `package.json`
  `dsh.profile.bundles` 引用；插件本体在 `profiles\web\node_modules`（pnpm 布局）。

## 执行步骤

1. **备份**：将升级前两棵 `@deepseek-ai` 目录全部包的版本清单导出到
   `过程记录\backup-dsh-versions-20260823-093708.txt`（393 行）。

2. **升级开发源**（`ds-harness-desktop\app`）：
   - `package.json`：`@deepseek-ai/dsh` `^0.1.0-rc.6` → `^0.1.1-rc.2`。
   - `npm install` 默认模式在巨型 peer 依赖树上卡死（>20 分钟 100% CPU 无进展，
     已 kill），改用 `npm install --legacy-peer-deps`（38 秒完成）。
   - 随后补齐 `--legacy-peer-deps` 跳过的 19 个 peer 包
     （`cordis-plugin-group`、`dsh-shell`、`dsh-workflow`、`dsh-invariants` 等，
     均 `^0.1.1-rc.2`；Linux-only 的 landlock 平台包不装）。
   - 结果：`app\node_modules\@deepseek-ai` = 197 个包，dsh@0.1.1-rc.2，lockfile 更新。

3. **升级运行态**（`产出\win-unpacked\resources\app\node_modules`）：
   - 用 robocopy `/MIR` 将 `app\node_modules` 完整镜像过去（排除 electron、
     electron-builder、.cache、.package-lock.json，与 `build/afterPack.js` 逻辑一致）。
   - 4 个原生文件因被运行中的 dsh 进程占用无法覆盖：`sharp` 的 libvips-42.dll /
     libvips-cpp / sharp .node 与 `koffi.node`。核对哈希：sharp 三文件与新版
     **完全一致**（同为 0.35.3，无需更新）；`koffi.node` 同版本 3.1.6 仅构建
     差异，运行中进程用内存副本，重启后即用新文件，不影响正确性。
   - `win-unpacked` 侧 `resources\app\package.json` 同步改为 `^0.1.1-rc.2`。

4. **同步 junction 农场**（`C:\Users\Administrator\.dsh\profiles\node_modules\@deepseek-ai`）：
   - 新增 6 个 junction：`dsh-client-ui-brand-official`、`dsh-client-ui-reference`、
     `dsh-client-ui-renderer`、`dsh-file-reference`、`dsh-file-reference-local`、
     `dsh-tool-pwsh-persistent`。
   - 删除 23 个失效 junction（旧版独有包），补齐 peer 包后再次同步。
   - 最终：农场 197 = win-unpacked 197，dangling junction = 0。

  树中仍含 `@liustack/modlens`、`dshmarket`、`dsh-convo-cost`、
  `@nanmicoder/dsh-auto-mode` ✓
- `profiles\web\package.json` 插件依赖未动：modlens@3.16.7 / dsh-auto-mode@^0.1.4 /
  dsh-convo-cost@^1.0.0 / dshmarket@1.5.0 ✓

## 注意事项（用户需知）

- **当前运行中的实例（PID 22344）仍跑旧代码（内存态）**；新版本在下次启动时生效。
  重启方式：关闭 `启动-DeepSeek-Harness.bat` 窗口后重新双击（或桌面版托盘退出再开）。
- `产出\` 下的安装器/便携版 exe 仍是旧构建；如需同步，在 `app\` 目录
  `npm run build` 重新打包即可（win-unpacked 会被 afterPack 用新 node_modules 覆盖，
  与本次手动镜像结果一致）。
- 升级过程中默认 npm 安装会卡死，故采用 `--legacy-peer-deps` + 手动补齐 peer 包，
  属已知 workaround；后续重建时建议同样处理或使用 pnpm。
