## 2. 根因分两层

1. **直接原因**：壳把「覆盖版本子进程退出」等价于「覆盖版本启动失败」，立即 `updater.deactivate()` →
   `state.json` 永久降级；而这次退出发生在**运行 4.6 小时之后**，与版本可用性无关。
2. **结构原因**：profile 依赖了只在 dsh ≥ 0.1.7 存在的 bundle，而壳的「保底 = 内置版本」在这台机器上
   从 9/25 15:52（语音输入初始化写入 bundle）起就**已经不成立** —— 回退目标注定起不来。

## 3. 修复内容（`app/src/main.js`、`app/src/updater.js`、`app/src/error.html`）

1. **判据收窄**：只有「从未成功加载过 UI（`reachedUi=false`）+ 仍在启动阶段（<60s 或 token 等待未结束）」
   才算启动失败；运行中途崩溃**不再改版本状态**。
2. **中途崩溃 → 同版本限次退避重启**（3 次 / 30 分钟滑动窗口；跑满 10 分钟且起过 UI 则清空预算），
   预算用尽只报错页。
3. **回退前预检**（`updater.checkProfileBundles`）：判据与上游 `dsh-app-boot` 的 `packageDirFromAnchor`
   **完全一致**（`createRequire(anchor).resolve.paths()` 父目录链 + 必须存在 `package.json`；锚点顺序：
   安装的 dsh 包 → profile 目录）。内置版解析不了当前 profile 就**不回退**。
4. **兜底自愈**：真回退后内置版也起不来 → 用 `fallbackFromVersion` 把 `state.json` 恢复回覆盖版本
   （只恢复一次，避免两版本互踢）；`bootstrap` 里「覆盖版本目录不可用」也不再无条件下调降级。
5. **可观测性**：错误页附 dsh 子进程日志尾部（**本次运行**的输出，令牌已脱敏）；子进程启动失败时跳过
   30 秒空等直接报真实原因；`spawn` 的 `error` 事件（exe 缺失/被杀软拦）纳入同一套判定。
6. **重启互斥**：`runHarnessOp` 串行化「停/起」（`restartHarness` 先同步停、起这一步排队），消除同秒双 spawn。
7. 托盘/菜单「回到内置版本」增加同一预检：注定打不开的回退**当场拒绝**并说明缺哪些 bundle。

## 5. 本机环境坑（下次照抄，别再踩）

- **agent 沙箱下「侧车 node.exe」只能写项目目录**（系统 node / PowerShell 不受限）：
  `afterPack` 的 `npm ci` 落在 `%TEMP%` → 必挂 `EPERM: mkdir`。绕过：打包时把
  `TEMP/TMP/npm_config_cache` 都指到仓库内（本次用 `.tmp-build`），并清空耗时约几分钟。
- **冒烟 `[4]` 必须 `--no-sandbox`**：不加会 1 秒退出 `code=2147483651 (0x80000003)`，与产物无关；
  手动复跑加 `--no-sandbox` 后产物可正常起 UI（A/B 已证：打过补丁的产物与未打补丁的 v0.3.8 表现一致）。
  **已落成开关**：`app/test/smoke.test.js` 新增 `DSH_SMOKE_EXTRA_ARGS`（只作用于体检自己拉起的
  隔离实例，隔离端口/userData/DSH_HOME，不碰真实安装与 `~/.dsh`）→
  `$env:DSH_SMOKE_EXTRA_ARGS='--no-sandbox'; npm run verify:smoke -- --packaged` 得 7/0/1。
  CI（普通 runner）不需要也不设该变量。
- **`%TEMP%\dsh-desktop-prod-deps\*` 里 9/30 16:22 的失败残留**：同一环境坑的历史痕迹（当日 Codex 构建也挂在这）。
- **超长路径删除**：`Remove-Item`/`rmdir` 会报 `Could not find a part of the path`，用
  `robocopy <空目录> <目标> /MIR` 清空后再删。

## 6. 新发现（上游行为差异，值得回报上游）

0.1.7-rc.2 的 bundle 解析**失败只跳过并告警**：
`dsh: skipping profile bundle "@…": Error: dsh: cannot resolve profile bundle …`；
而内置 0.1.5-rc.1 是 **throw、整个 boot 失败**（事故堆栈即出自它）。
即事故报告第 8 节的建议 1（bundle 缺失不应导致 boot 失败）**上游已在新版本实现**。
