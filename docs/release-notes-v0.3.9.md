# v0.3.9 Release Notes（草稿：发布时直接贴到 GitHub Release 描述）

## 修复

- **桌面端会「永久打不开」的降级缺陷（2026-09-30 事故根因）**：外壳把「覆盖版本 dsh
  子进程退出」一律等价于「覆盖版本启动失败」。9/30 21:50 那次子进程是在**正常运行
  4.6 小时之后**静默退出的（`code=1`、无堆栈、无系统事件），外壳却据此在 4 毫秒内
  写入 `state.json` 永久降级到内置版本；而该 profile 依赖了只在 dsh ≥ 0.1.7 存在的
  `@deepseek-ai/dsh-experimental-voice-input-bundle`，内置 0.1.5-rc.1 永远解析不了它，
  于是此后每次启动都崩在 bundle 解析，界面只显示「harness 服务未在预期时间内就绪」。
- **判据收窄**：只有「从未成功加载过 UI **且**仍在启动阶段（60 秒内，或 token 等待
  未结束）」才判定为启动失败；**运行中途崩溃不再改动版本状态**，改为按同一版本限次
  退避重启（3 次 / 30 分钟滑动窗口，跑满 10 分钟且起过 UI 则清空预算）。
- **回退前先问「回退有用吗」**：新增 `updater.checkProfileBundles`，判据与上游
  `dsh-app-boot` 的 `packageDirFromAnchor` 完全一致（`createRequire(anchor).resolve.paths()`
  父目录链 + 必须存在 `package.json`）。内置版本解析不了当前 profile 时**不回退** ——
  回退过去只会把用户锁死在注定起不来的版本上。
- **兜底自愈**：真回退后若内置版本也起不来，自动把 `state.json` 恢复到被停用的覆盖版本
  （只恢复一次，避免两个版本互相踢皮球）；`bootstrap` 阶段「覆盖版本目录不可用」也不再
  无条件下调降级。
- **错误页给出真实原因**：附 dsh 子进程日志尾部（只显示**本次运行**的输出，启动令牌已
  脱敏），不再是「服务未在预期时间内就绪」这种零信息文案；子进程能够立即判定死亡时不再
  空等 30 秒就绪探测；`spawn` 失败（exe 缺失 / 被杀软拦下）也纳入同一套判定。
- **重启互斥**：串行化 harness 的「停 / 起」操作，消除「同一秒两次重启拉起两个子进程、
  手机中继同时占用两个端口」的竞态。
- **托盘「回到内置版本」加预检**：注定打不开的回退当场拒绝，并说明缺哪些 bundle（此前
  它等于一个「一键打不开」按钮）。

## 验证

- 离线单测 `npm test`：**32/32**（新增 8 个用例，覆盖父目录链命中、空目录不算命中等）。
- 预检判据与上游算法在真机两侧安装根**逐条一致**（内置 0.1.5-rc.1：11 个 bundle 缺 2 个；
  覆盖版 0.1.7-rc.2：缺 0 个）。
- `npm run build`：打包 + 冒烟体检 `失败 0`（[5] 安装器端到端在本机有正式实例时按设计跳过）。
- **端到端（真实 Electron 产物 + 隔离端口 / userData / DSH_HOME）**：
  - 覆盖版本正常运行中**硬杀子进程**（复刻 9/30 现场：`code=1`、`signal=null`）→ 日志
    `[recovery] 运行中途崩溃 → 1 秒后按同一版本重启` → 新进程重新监听、UI 重新加载，
    **`state.json` 全程未被改写**；
  - 覆盖版本启动失败 + 内置版本解析不了 profile → 日志 `跳过回退`，重试预算用尽后报错页，
    **`state.json` 仍保持覆盖版本**（旧版本此处会写成 `null`，即本次事故的永久锁死）。

## 升级方式

- 安装版：托盘「检查桌面端更新」自动下载安装；或从 Releases 下载
  `DS-Harness-Desktop-Setup-0.3.9.exe` 覆盖安装。
- 便携版：从 Releases 重新下载 `DS-Harness-Desktop-0.3.9-portable.exe` 替换旧文件。
- 升级弹出向导时**保持默认「全机」模式、不要切换「仅当前用户」**（切错会产生双安装 /
  孤儿安装）；升级后可查看 `resources\app\package.json` 确认版本为 0.3.9。
- 若曾手工改过 `dsh-update\state.json`（9/30 的手工恢复），升级不会覆盖它；正常升级即可。

## 已知限制

- 便携版无法原地自更新（既有限制，需手动下载新文件替换）。
- **dsh 本体的启动冒烟验证用干净的临时 `DSH_HOME`，不含第三方插件**，因此发现不了
  「引擎升级导致第三方插件不兼容」这一类失败；升级 dsh 前后请先更新插件。
- 当**覆盖版本与内置版本都无法加载当前 profile** 时，界面上目前没有「重装 / 修复当前
  dsh 版本」的入口（错误页只有「重启服务」）—— 本轮未做，已记入待办。
