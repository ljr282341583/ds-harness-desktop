# DS Harness Desktop — 设计方案

> 日期：2026-08-14 ｜ 状态：已确认（grill-me 访谈产出）｜ 范围：首版（v1）

## 1. 目标

把 DeepSeek Harness（`@deepseek-ai/dsh`）从「浏览器 Web GUI」形态封装为 Windows 桌面应用：原生窗口 + 系统托盘，后端复用现有 `dsh web`，UI 复用现有 web 前端，不新增功能（纯壳）。

## 2. 决策树（已确认）

| # | 分支 | 决定 | 理由 |
|---|---|---|---|
| 1 | 形态 | 原生壳包裹现有 Web UI | 复用全部现有 UI 与工具链，风险最低 |
| 2 | 壳框架 | Electron | Node 同源，bash/pwsh/fs/subagent 等工具零桥接 |
| 3 | 后端运行 | 托管子进程 `dsh web` | 走公开 CLI 契约、崩溃隔离、升级独立 |
| 4 | UI 加载 | `loadURL` 本地服务地址 | 完全复用 web 前端 + apiproxy/ws，保真度最高 |
| 5 | 关闭窗口 | 最小化到托盘 | 符合 DSH 常驻 Agent 定位 |
| 6 | 端口 | 默认 3080，冲突自动找空闲端口 | 稳定地址 + 永不硬失败 |
| 7 | 目标平台 | 首版仅 Windows | 与开发环境一致，Electron 不锁死后续扩展 |
| 8 | 打包 | NSIS 安装器 + portable exe | electron-builder 成本几乎为零 |
| 9 | dsh 来源 | 应用内捆绑固定版（用独立 Node 24 侧车运行） | 自包含、版本可复现、开箱即用；实测 Electron 自带 Node 版本过低，无法运行 DSH |
| 10 | 更新 | 首版手动检查更新 | 免签名证书/发布源基建 |
| 11 | 首版范围 | 纯壳 | 先立住桌面形态 |
| 12 | 数据目录 | 复用 `~/.dsh` | 凭据/会话/skills/profiles 开箱即用 |

## 3. 架构

```
┌───────────────────────────── Electron 应用（单实例）─────────────────────────────┐
│                                                                                    │
│  main（主进程）                                                                     │
│   ├─ 单实例锁（二次启动 → 聚焦已有窗口）                                              │
│   ├─ 端口解析（默认 3080 → 冲突则 3081/3082…）                                       │
│   ├─ 子进程管理：spawn dsh web --port <p>                                            │
│   │     · 用 Electron 自带 Node 运行捆绑的 @deepseek-ai/dsh/lib/bin.js               │
│   │     · 就绪探测：轮询 http://127.0.0.1:<p>/ 直至响应                               │
│   │     · 崩溃 → 错误页 + 「重启服务」；退出 → 优雅终止子进程                          │
│   ├─ BrowserWindow：loadURL http://127.0.0.1:<p>/                                    │
│   ├─ Tray：显示窗口 / 重启服务 / 检查更新 / 退出                                       │
│   └─ 关闭窗口 = 隐藏到托盘（不退出）                                                  │
│                                                                                    │
│  preload（contextBridge，最小暴露）                                                  │
│                                                                                    │
└────────────────────────────────────────────────────────────────────────────────────┘
        │ spawn（ELECTRON_RUN_AS_NODE=1）
        ▼
┌───────────────────────────────┐
│  dsh 子进程（web profile）       │
│  webserver + 静态前端 + apiproxy │
│  数据目录：~/.dsh（共享）        │
└───────────────────────────────┘
```

## 4. 实现要点

### 4.1 子进程启动

- 入口：`node_modules/@deepseek-ai/dsh/lib/bin.js`（`require.resolve('@deepseek-ai/dsh/package.json')` 定位）。
- 命令：`<node.exe> bin.js web --port <p>`。
- 运行时：**捆绑的独立 Node 24 侧车**（`runtime/node.exe`），不是 Electron 自带 Node。
- 原因（实测验证）：DSH 依赖 Node 22.15+ 的新 API —— `node:zlib` 的 `createZstdDecompress`/zstd 系列、`node:module` 的 `stripTypeScriptTypes`；Electron 33 自带 Node 20.18 缺这些导出，直接跑 dsh 会崩。故捆绑独立 Node 24 侧车运行 dsh，Electron 只做壳。

### 4.2 端口解析

- 默认 `3080`；用 TCP 探测，被占用则自增直到空闲（上限 10 次，否则报错）。

### 4.3 就绪探测与错误处理

- 轮询 `GET http://127.0.0.1:<p>/`（间隔 250ms，超时 30s），收到任意 HTTP 响应即视为就绪。
- 未就绪/子进程提前退出 → 窗口显示内置错误页（本地 `file://` 或 `data:`），提供「重启服务」。
- 子进程 `exit` 事件在应用未退出时触发 → 弹错误页，托盘「重启服务」可用。

### 4.4 生命周期

- 单实例：`app.requestSingleInstanceLock()`；`second-instance` 事件 → 显示并聚焦已有窗口。
- 关闭窗口：`close` 事件 `preventDefault` + `hide()`（应用 `will-quit` 前标记真实退出）。
- 托盘「退出」→ 置 `quitting = true` → `app.quit()`；`before-quit`/`will-quit` 中向子进程发终止信号并等待退出。
- Windows 终止子进程：优先 `child.kill()`（SIGTERM 对 Node 有效），超时则 `taskkill /pid <pid> /T /F` 兜底。

### 4.5 打包

- electron-builder，配置 `win.target = [nsis, portable]`。
- `files` 打包主进程源码 + `node_modules`（含捆绑的 `@deepseek-ai/dsh` 及依赖）。
- `asar: false`：dsh 由独立 Node 侧车执行，侧车不识别 asar，故整个应用以普通文件落盘。
- `extraResources`：把 `runtime/`（Node 24 运行时）复制到 `resources/runtime`，主进程据此 spawn dsh。
- 产物落 `产出\`。

### 4.6 更新（v1 手动）

- 壳内置「检查更新」：比对远端 `latest.yml`/manifest 版本，有新版提示并打开下载页。
- 具体渠道（GitHub Releases / 自建静态源）在发布前确定。

## 5. 安全与凭据

- 桌面版复用 `~/.dsh`，凭据由 DSH 自身管理（`.credentials.yaml`），本项目不落任何密钥。
- BrowserWindow 启用 `contextIsolation: true`、`nodeIntegration: false`；preload 仅经 `contextBridge` 暴露只读应用信息（版本、端口等）。
- 本地服务绑定 `127.0.0.1`，不对外暴露。

## 6. 验收标准（v1）

1. 双击可启动，单实例生效。
2. 自动拉起捆绑的 dsh，窗口加载现有 web UI（含会话、工具、settings）。
3. 端口冲突时自动切换并正常工作。
4. 关闭窗口 → 隐藏到托盘；托盘「退出」→ 应用与 dsh 子进程都干净退出。
5. dsh 子进程崩溃 → 显示错误页，可「重启服务」恢复。
6. 打包出 NSIS 安装器与 portable exe，安装后可正常运行。
7. 复用同一 `~/.dsh`，现有凭据/会话/skills 直接可用。
